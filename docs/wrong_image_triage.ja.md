# 「画像が違う」場合の切り分けと報告

## まず確認すること

問題の地点を一つ選び、次の項目を順に確認します。番号の一致だけでは、画像内容が正しいとは判断しません。

1. **選択地点**: 軌跡のどの地点を選んだか。動画を通常再生したとき、その付近はどんな場面か。
2. **パネル**: フレーム番号が変わったか。プレビュー内容は選んだ地点に合っているか。
3. **Webビューア**: フレーム番号はパネルと同じか。画像内容はパネルと同じか。Loadingやエラーが残っているか。
4. **生成JPEG**: 必要に応じて、同じフレーム番号の`images`の画像と、Webが取得したJPEGを直接確認する。

「変わらない」と「変わるが違う場面」を区別します。Webが取得したJPEGはブラウザの開発者ツールのNetworkから、その画像リクエストのURLを新しいタブで開いて確認できます。ファイル名に要求番号が付いていても、中身の正しさの証明にはなりません。

## 切り分け表

以下は調査先の目安であり、原因の断定ではありません。

| 確認結果 | 次に調べる場所 |
| --- | --- |
| 地点を変えてもパネルの番号が変わらない | 地点選択、ナビゲーションモード、選択レイヤ |
| パネルの番号は変わるが、生成JPEGも違う場面 | 地点とフレームの対応、動画の選択、OpenCVのシーク・読み出し、画像の再利用 |
| パネルは正しいがWebの番号が違う | 表示指示・状態の同期、接続しているサーバ |
| 番号は一致するがWeb側のJPEGが違う | サーバの所属・コードの世代、Web側の読み出し、キャッシュ |
| Web側のJPEGを直接開くと正しいが、360表示だけ違う・更新されない | ビューアの画像適用処理、ブラウザ、描画環境 |
| 新しい番号でLoading・HTTPエラーになり、前の画像が残る | 新しい画像の取得・適用失敗。現在表示中の画像を新しい番号の画像と扱わない |

Webの状態JSONに新しい番号や適用済みIDがあっても、それだけで画像の読み込み完了を保証するわけではありません。現行のビューアには画像適用の完了前に状態を更新する経路があります。

## 最初の報告テンプレート

初回は内部ログを全部収集する必要はありません。不明な項目は不明と記入します。

```text
QGIS / Geo360View / OSの版:
動画名・解像度（分かればコーデック）:
選択した地点と期待する場面:
行った操作（次へ、前へ、地図クリック、POI選択など）:
パネルのフレーム番号: 操作前 → 操作後
パネルの画像: 正しい / 変わらない / 変わるが違う / エラー
Webのフレーム番号: 操作前 → 操作後
Webの画像: 正しい / 変わらない / 変わるが違う / Loading / エラー
発生する範囲: この地点だけ / この動画全体 / 複数の動画 / 不明
エラー表示の内容:
再起動・サーバ停止などで改善したか（既に試した場合）:
```

可能なら、同じ操作直後の地図・パネル・Webの表示を記録します。利用者に同じ操作を何度も要求する前に、まずこの情報で調査先を絞ります。

## 調査担当者が追加確認する情報

- health APIの設定パス、PID、コード指紋、所属する起動元。旧版には一部の項目がない。
- 対象JPEGリクエストのURL、HTTPステータス、`X-Frame-Index`、`X-Frame-Source`。
- パネルで保存したJPEGとWebが取得したJPEGの実際の内容。
- パネルとサーバそれぞれのPython実行パス、OpenCVの版・導入パス・ビルド情報。
- 同じ動画の同じフレームで、順読みとシークの結果に違いがあるか。

サーバ停止・キャッシュ退避を試す前に、可能なら上記の状態を保存します。復旧操作が原因の手がかりを消すことがあります。停止は[サーバ残存時の復旧手順](viewer_server_recovery.ja.md)に従い、対象PIDと所属を確認します。

- 読み込み失敗時は、前の画像が残っていることを明示する。
- サーバの所属・実行中コード・抽出結果をまとめた診断情報をコピーできるようにする。
