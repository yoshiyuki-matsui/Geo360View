### ライブラリの診断証拠

| 環境 | cv2読み込み元 | FFmpeg（avcodec / avformat / avutil / swscale） | スレッド指定API |
|---|---|---|---|
| Windows 3.40 | ユーザのPython312 `site-packages/cv2` | 61.19.100 / 61.7.100 / 59.39.100 / 8.3.100（ビルド情報） | あり |
| 会社Ubuntu | `/usr/lib/python3/dist-packages/cv2…so` | 60.31.102 / 60.16.100 / 58.29.100 / 7.5.100（ロード済み） | なし |
| 自宅Ubuntu・最終 | `~/.local/share/Geo360View/opencv-4.8.1/cv2` | 59.37.100 / 59.27.100 / 57.28.100 / 6.7.100（wheel内、ロード済み） | あり |

Ubuntu両環境でQGISとWebサーバ双方の読み込み元・版を診断で確認しました。Windows 3.40の提示診断ではWeb側の取得が失敗し、その後の正常時診断は未採取です。

自宅の通常起動でも2026-10-09T02:52:55Zに、QGIS PID359843・Web PID359935がシステムOpenCV 4.6.0とFFmpeg 60系を使うことを確認しました。診断用変数は未設定、スレッド指定APIはありません。利用者が続けて別フレーム3933を要求するとHTTP 422になり、先の正常表示はキャッシュによるものと報告しました。4.6の問題は解消していません。今回の422の本文・サーバログは未取得で、具体的な拒否理由は未確定です。

その後、OpenCV 4.8.1を指定して再起動し、利用者が正常動作を再確認しました。2026-10-09T03:01:11Z（JST 12:01）の診断ではQGIS PID365842・Web PID365926とも専用配置の4.8.1を読み込み、スレッド指定APIあり、設定上限8、`LD_PRELOAD`と`GEO360_PROBE_THREADS`は未設定です。ロード済みFFmpegも双方でwheel内の59系に一致しています。再確認時の具体的なフレーム番号・キャッシュ利用状況は個別未記録です。

`configured_decoder_thread_limit=8`は設定方針で、稼働中デコーダの実測値ではありません。OpenCV汎用処理のスレッド数（自宅20）は別の値です。

## 自宅の異常再現と回避

比較動画のSHA256は自宅とNASで一致しました。

```text
174cbda58bbdacaa226875cd5e30cd50fc10c92c4092b41e20676a8559d3049c
```

OpenCV 4.6、同じ動画・フレーム9571を新しいプロセスで読み出し、デコードスレッド数を変更した診断結果:

| 設定 | シーク後 / 読取後位置 | 画像・結果 | シーク時間 |
|---|---|---|---|
| 既定（デコーダ20） | 巨大な負数 | 起点の誤画像 | 約3.56秒 |
| 8 | 9571 / 9572 | 指定箇所の正しい画像 | 約1.03秒 |
| 16 | 巨大な負数 | 異常位置、画像保存あり | 約3.62秒 |
| 20 | 巨大な負数 | 異常位置、画像保存あり | 約3.55秒 |

診断用ライブラリによる8スレッド制限で、QGISからも正常・以前より高速と報告されました。その後、`opencv-python-headless==4.8.1.78`を専用配置し、診断用介入なしで正常動作を確認しました。

通常起動4.6で別フレームのHTTP 422を確認した後、診断用`LD_PRELOAD`方式での正常動作も再報告されました。この方式はOpenCVの版を変更しません。最終の4.8.1指定起動による確認とは区別します。

4.8.1では内蔵FFmpegと並列処理方式も変わるため、更新後の改善をスレッド指定単独の効果とは断定しません。全動画で8スレッドが安全という保証や、ライブラリ内部の根本原因の特定には至っていません。

## HTTPサーバと配布物

- 古いサーバの残存で誤画像・起動拒否が発生し、対象を停止して正常化した例があります。
- Windowsでは管理PIDと待受PIDが一致した後、別時点の接続が拒否されました。終了原因ログがないため原因は未確定です。
- 手動比較ではOSGeo4W Shellが4.2.2側、指定Pythonが3.40側だった例もあり、起動環境差を考慮します。
- 手動サーバはQGIS終了では止まりません。Ctrl+Cで停止してからプラグイン起動を比較します。
- 比較ZIPはすべて0.5.6表記で、内容が異なります。各環境の最終試験に使ったZIPのSHA256は未記録です。
- Ubuntu診断の`server_build=7f5a0311…`はサーバと一部ヘルパーの指紋で、ZIP全体の一致を証明しません。
- 公開済み0.5.5 ZIPは変更していません。
