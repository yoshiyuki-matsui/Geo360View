# POI Center お品書きメモ

このメモは、360走行データから生成したいAI候補レイヤを、道路事務所や担当課と相談するための
「お品書き」として整理するものです。

狙いは、技術名やモデル名ではなく「何を見たいか」「いつ見たいか」「どの程度の検品が必要か」を
先に決めることです。撮影データ、NAS、GPU処理、QGIS、360証跡ビューアは共通基盤とし、
見たい対象ごとにモデル、推奨face、後処理、検品レベルを足します。

## 基本コンセプト

```text
撮影する
NASに置く
AI候補レイヤを生成する
QGISで見る
360証跡で確認する
必要箇所だけ現地確認する
```

地図を新しく作るのではなく、既存地図やKP管理の上に、維持管理で見たいPOI候補を載せます。
POIは図面上の精密図形ではなく、確認対象へたどるための空間インデックスです。

## 注文シート項目

担当課ごとに、次の項目を埋めてもらう想定です。

| 項目 | 内容 |
| --- | --- |
| 担当課 | 道路保全、施設、構造物、植栽、交通管理など |
| 見たいもの | お品書きから選択、または自由記述 |
| 対象区間 | 路線、上下線、KP、道路事務所管内 |
| 希望頻度 | 月次、四半期、梅雨前、台風前後、工事期間中など |
| 希望成果物 | QGISレイヤ、HTMLレポート、CSV、現地確認リスト、ヒートマップ |
| 精度要求 | 候補レベル、簡易検品、詳細検品、台帳更新候補 |
| 優先度 | 通常、急ぎ、災害対応、点検前 |
| 専用モデル要否 | 標準モデルで試す、専用モデルを作る、既存モデルを改善する |

## 検品レベル

| レベル | 位置づけ | 主な用途 |
| --- | --- | --- |
| Level 1 Signal | AIが粗く拾ったヒント。低confや概略位置も含む | まず見る、現地確認候補を広く出す |
| Level 2 Candidate | 複数フレーム支持、証跡あり、位置や方向がある程度安定 | 担当課レビュー、優先度付け |
| Level 3 Accepted POI | レビュー済み、重複整理済み、位置品質/証跡付き | 納品候補、台帳更新候補、補修判断補助 |

## 運用メモ

- 高精度が必要なメニューは、RTK/GNSS-BeatBoxと同期調整を推奨します。
- 即応性が重要なメニューは、Insta360 + スマホGNSSでも候補抽出として有効です。
- 遠方対象は地図上の点を精密図形として扱わず、視線方向と360証跡への入口として扱います。
- CubeMap画像は中間生成物として扱い、元動画、GPX/GNSS、DB、GPKG、レポート、モデル設定を残せば再現可能です。
- 専用モデルは、CubeMap画像から数百枚のseed datasetを作り、digによる自動アノテーションとレビューで育てます。
- HighwayAIMonitor由来のヒヤリハットPOIは、YOLO単体ではなく、映像、GNSS、加速度、イベント時系列を重ねた安全リスク候補として扱います。
- 工事規制、除雪作業、雪捨て候補のような情報/運用系POIは、YOLO検出だけでなく、広報、作業ログ、台帳、無雪期360などを取り込むエージェントで生成します。
- 水たまり/路面凹部は「冷やし中華始めました」型の季節メニューです。雨天後の見え方を利用して、乾燥時には見えにくい凹部や排水不良を拾います。
