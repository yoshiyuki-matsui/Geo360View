# QGIS手動テストチェックリスト

更新日: 2026-06-07

この文書は、Geo360Viewを人に触らせる前にQGIS実機で確認する項目を機能単位で整理したものです。

入力値の境界、不正ファイル、JSON検証、Exporter抽出条件などの細かい判定はユニットテストへ寄せます。ここではQGIS UI、MapTool、外部ブラウザ、RubberBand、OpenCV、実ファイルI/Oをまたぐ動作を目視確認します。

## 記録欄

- 確認日:
- 確認者:
- OS:
- QGIS:
- Python/OpenCV:
- ブラウザ:
- krpano.js: あり / なし
- 入力GPX:
- 入力MP4:
- KP CSV:
- 出力先:
- 備考:

判定は `OK` / `NG` / `保留` とし、NGまたは保留は再現手順、フレーム番号、ログ、スクリーンショット有無を残します。

## 1. 起動・終了

- [ ] QGIS起動後、プラグインメニューに `360Viewer起動` / `操作パネル` / `終了` が表示される。
- [ ] `操作パネル` でパネルが表示され、QGIS操作中も前面に残る。
- [ ] `操作パネル` 時に360Viewerの起動状態がmessageBarへ表示される。
- [ ] `終了` で操作パネルが閉じる。
- [ ] `終了` 後、プラグインが作成したレーダ表示が地図上に残らない。
- [ ] `終了` 後、プラグインが起動した360Viewerプロセスが終了する。
- [ ] `終了` 後、他の手作業レイヤや地物登録プラグインの状態を壊さない。

## 2. Load / Process入力

- [ ] GPXを選択すると、パネル上にファイル名が表示され、ツールチップでフルパスを確認できる。
- [ ] MP4を選択すると、パネル上にファイル名が表示され、既定出力先がMP4名由来のフォルダへ更新される。
- [ ] KP CSVを選択すると、パネル上にファイル名が表示される。
- [ ] 出力先を指定すると、パネル上にフォルダ名が表示される。
- [ ] GPX未指定、MP4未指定などの不足入力で `全件処理` してもworkerが開始せず、messageBarに入力エラーが出る。
- [ ] 存在しないファイルや拡張子違いを設定した状態で `全件処理` してもworkerが開始しない。
- [ ] `Shift` は正負ともに設定でき、結果の `frame` は動画上の不変番号、`source_frame` は位置参照元として出力される。
- [ ] `KP tol` を変更した場合、KPマッチ件数が許容距離に応じて変化する。

## 3. Process結果

- [ ] `全件処理` 実行中、進捗バーが更新される。
- [ ] 正常終了後、`Video GPX Points` レイヤが追加される。
- [ ] レイヤ属性に `frame` / `source_frame` / `frame_shift` / `timestamp` / 緯度経度 / KP関連列がある。
- [ ] 地図上の撮影点が想定位置に表示される。
- [ ] `*_frames.csv` が出力先に保存される。
- [ ] KP CSV指定時、`*_navigation.json` と `*_matched_frames.csv` が保存される。
- [ ] KP CSV未指定時、全フレーム位置情報は生成され、KP列は未マッチ扱いになる。
- [ ] `tmp.gpkg` 保存前にQGISを閉じない運用であることを確認する。

## 4. 360Viewer起動

- [ ] `360Viewer起動` でローカルHTTPサーバが起動する。
- [ ] 外部ブラウザで `http://127.0.0.1:8181` または設定portのビューアが開く。
- [ ] krpano.jsがある場合、360表示が開く。
- [ ] krpano.jsがない場合、エクイレクタングラー画像のフォールバック表示になる。
- [ ] `viewer_session.json` と `viewer_cache/` が出力先配下に作成される。
- [ ] `CamH` を変更すると、`viewer_session.json` の `viewer_camera_height_m` に保存される。
- [ ] 既存ジョブの出力先を再選択すると、`viewer_session.json` の `viewer_camera_height_m` が `CamH` 入力へ復元される。
- [ ] ビューア起動済みの状態で再度 `360Viewer起動` しても不要な二重プロセスにならない。

## 5. フレーム抽出・プレビュー

- [ ] `Frame` にフレーム番号を入れて `抽出` すると、該当JPEGが生成される。
- [ ] 生成先が `images/0000/frame_0000000.jpg` 形式の1000件単位階層になる。
- [ ] 同じフレームを再表示すると抽出済みJPEGが使われ、再抽出されない。
- [ ] パネル内プレビューが更新される。
- [ ] プレビュー情報行に `Frame ... 保存/既存` と `images/` 側のファイル名・処理時間が表示される。
- [ ] 一見同じ画像でも、プレビュー情報行のframe番号またはファイル名で切替を確認できる。
- [ ] プレビュー画像上のtooltipに `viewer_cache/` 側の想定ファイル名が表示される。
- [ ] WEBビューア表示後、tooltipに表示された `viewer_cache/` ファイルが実際に存在する。
- [ ] `viewer_cache/` ファイルが存在する場合、tooltipにサイズが併記される。
- [ ] JPEGのEXIFにプログラム名、説明、日時、緯度経度が入る。
- [ ] 動画を読めない場合やOpenCVがない場合、QGISが落ちずmessageBarへ警告が出る。

## 6. 地図クリック連携

- [ ] `撮影点選択` でクリックモードが有効になる。
- [ ] `Video GPX Points` をクリックすると、対応フレームがビューアへ表示される。
- [ ] クリックされた撮影点が一時ハイライトされる。
- [ ] `選択解除` でクリックモードが解除される。
- [ ] `選択解除` 後にハイライトが残らない。
- [ ] `Video GPX Points` 以外のレイヤが選択されている場合、適切な警告が出る。

## 7. キーボードナビゲーション

- [ ] 操作パネルにフォーカスがある状態で `←` / `→` によりフレーム移動できる。
- [ ] `Shift + ←` / `Shift + →` によりFast stepで移動できる。
- [ ] `Space` で現在フレームを再表示できる。
- [ ] `Esc` でクリックモードを解除できる。
- [ ] 数値入力やコンボボックス編集中は、矢印キーが入力操作として扱われる。
- [ ] 既存の地物登録プラグインがMapToolを持っている状態でも、操作パネルにフォーカスがあればナビゲーションできる。
- [ ] `Nav` が `Frame step` / `Layer point` / `KP matched CSV` / `Marking` / `Detection check` の各モードで期待通り移動する。
- [ ] `|<<` / `>>|` で、現在Nav対象の先頭/最後尾へ移動できる。
- [ ] `KP matched CSV` がない状態で `KP matched CSV` モードを使うと、警告が出て `Frame step` へ自動的に戻る。
- [ ] GPKG内に `poi_candidates_360` がある場合、`Detection check` がその候補フレームだけを辿る。
- [ ] GPKG内に `poi_candidates_360` がなく `poi_candidates_pothole_360` などモデル別候補レイヤだけがある場合も、`Detection check` が候補フレームだけを辿る。
- [ ] GPKG内の候補レイヤがQGIS上で `360 Detection Candidates: <layer_name>` として読み込まれる。
- [ ] GPKG内のクラスタレイヤがQGIS上で `360 POI Clusters: <layer_name>` として読み込まれる。
- [ ] `Detection check` の `Scope=Active layer` で、アクティブ候補/クラスタレイヤだけを辿る。
- [ ] `Detection check` の既定Scopeが `Visible layers` で、QGIS表示ONの候補/クラスタレイヤだけを辿る。
- [ ] `Detection check` の `Scope=All candidates` で、読み込まれている候補/クラスタレイヤ全体を辿る。
- [ ] `Detection check` の `Scope=Selected features` で、選択中featureだけを辿る。
- [ ] QGISのsubset filterで `semantic_class` などを絞ると、Nav対象も同じ絞り込み結果になる。
- [ ] `Detection check` でフレーム移動すると、同一frameのYOLO候補が360ビューア上に候補マーカーとして復元される。

## 8. Followと地図中心移動

- [ ] `Follow` OFFでは、フレーム移動しても地図中心が勝手に移動しない。
- [ ] `Follow` ONでは、表示フレームの撮影点へ地図中心が移動する。
- [ ] `Follow` ONでも地図縮尺が勝手に変わらない。
- [ ] 連続フレーム送り時、地図描画の遅延が許容できる。

## 9. レーダ表示

- [ ] ビューアのyaw/pitch/zoom変化がQGIS地図上のレーダへ反映される。
- [ ] 5m/10mなどの同心円がQGIS計測ツールで概ね実寸と一致する。
- [ ] 進行方向が移動軌跡から推定される。
- [ ] `Offset` 0/90/180/270で動画正面方向の補正が意図通り変わる。
- [ ] `CamH` 変更後、WEBビューア上の5m/10m地面範囲円が更新される。
- [ ] WEBビューア上で1m間隔の薄い破線補助グリッドが表示される。
- [ ] QGIS地図上にも1m間隔の補助円が表示され、WEBビューア側の1mグリッドと同じ距離目安として読める。
- [ ] `HUD` ボタンでWEBビューア上の主円、1m補助グリッド、距離HUDがまとめて表示/非表示になる。
- [ ] `Range=10m` のとき、主円は10m/20mで、補助グリッドは1m間隔のまま表示される。
- [ ] 人の足元、標識柱の根元、路面標示、縁石、マンホールなど、地表面上の点で距離目安を確認する。
- [ ] `CalFOV` / `CalDist` / `Scale` 変更で垂線距離が変わる。
- [ ] ズームイン時に垂線距離が近くなり、ズームアウト時に遠くなる。
- [ ] WEBビューアHUDの距離目安とQGIS側レーダの前提が一致する。
- [ ] フレーム移動後もyaw/pitch/zoomが維持され、レーダ向きも継承される。

## 10. Marking

- [ ] WEBビューア上で気になる対象をダブルクリックすると、Markingが保存される。
- [ ] WEBビューア上で複数箇所をダブルクリックすると、クリック順の複数MarkingがQGIS地図上に緑の仮投影点として表示される。
- [ ] ダブルクリック後にWEBビューアのyaw/pitch/zoomを変更しても、WEB上のマーカーが同じ360球面位置に追従する。
- [ ] `Geo360 Markings` レイヤが作成され、投影点の緯度経度と `video` / `frame` / `target_id` が属性テーブルへ保存される。
- [ ] 視点移動で `viewer_session.json` が更新されても、同じ `video` / `frame` / `target_id` のレコードが重複追加されない。
- [ ] Markingを置いたフレームを再表示すると、保存済みMarkingがWEBビューア上に復元表示される。
- [ ] 別動画由来の `geo360_markings` / `click_targets_360` 相当レイヤを同時に開いても、現在MP4と一致しない点は復元されない。
- [ ] 投影点の方向がビューア内のクリック方向と整合する。
- [ ] 投影点の距離が `CalFOV` / `CalDist` / `Scale` と連動する。
- [ ] 真横に近いクリックなど角度が大きい場合でもQGISが落ちない。
- [ ] RubberBandの緑点・緑線は一時表示であり、`終了` 後に残らない。
- [ ] `Geo360 Markings` は生成レイヤとして `tmp.gpkg` に保存され、`geo360_markings` レイヤとして再読込できる。
- [ ] 旧GPKGの `click_targets_360` は互換レイヤとして再読込できる。
- [ ] GPKG読込で `video_gpx_points` が `Video GPX Points` メモリレイヤへ読み替わり、ナビゲーション対象になる。
- [ ] GPKG読込で `geo360_markings` が `Geo360 Markings` メモリレイヤへ読み替わり、追加Markingと同じレイヤで扱われる。
- [ ] GPKG読込で、保存時のGPX/KP CSV由来パス、`Shift`、`KP tol`、`Range`、`Scale`、`Offset`、`CalFOV`、`CalDist`、`CamH` がパネルへ復元される。
- [ ] GPKG読込で、保存時のMP4パスはファイル実体が存在する場合だけ動画パスとして復元される。
- [ ] GPKG読込時、Markingがある場合はナビゲーションモードが `Marking` になり、Markingがあるフレームだけを前後移動できる。
- [ ] `Marking` 前後移動では、現在のユーザ視点ではなく保存済みの `view_yaw` / `view_pitch` / `view_zoom` が再現される。
- [ ] Markingが表示された状態でスナップショットを保存すると、Markingマーカーが画像内に描かれる。
- [ ] スナップショット画像と `Geo360 Markings` レコードを `frame` で対応付けできる。
- [ ] GPKG読込後、GPX/MP4/KP/Outputの再選択、`Shift`、`KP tol`、`全件処理`、別GPKG読込が無効化される。
- [ ] GPKG読込後に追加したMarkingが、`終了` 後に同じ `tmp.gpkg` の `geo360_markings` へ保存される。

## 11. 他プラグインとの共存

- [ ] 地物登録プラグインで登録先レイヤを自由に切り替えられる。
- [ ] Geo360View側のレイヤをアクティブにしなくてもフレーム移動できる。
- [ ] 地物登録中にビューア画像を送りながらポイント登録できる。
- [ ] Geo360Viewの `終了` で地物登録プラグインのMapToolや編集中レイヤを壊さない。

## 12. エラー表示と言語

- [ ] 英語localeではmessageBarが英語で表示される。
- [ ] `GPX_VIDEO_PROCESSOR_LOCALE=ja` の場合、日本語messageBarが表示される。
- [ ] 日本語localeでは、メニュー、タブ、主要ボタン、チェックボックスが日本語で表示される。
- [ ] `Shift`、`KP tol`、`CamH`、`CalFOV`、`CalDist`、`Scale`、`Offset` などの技術ラベルは短い英語/略称のまま表示される。
- [ ] 主要操作、技術ラベル、プレビュー画像へマウスを置くと、簡潔なtooltipが表示される。
- [ ] 入力検証エラーは「何を直せばよいか」が分かる短い文で表示される。
- [ ] Python tracebackが通常ユーザ向けmessageBarへ直接出ない。
- [ ] 重要な詳細はQGISログまたはPythonコンソール側で追える。

## 13. 連続操作の簡易確認

- [ ] 50回程度の連続フレーム送りでビューア、QGIS、レーダが追従する。
- [ ] 連続クリックでキャッシュが増えても操作が著しく重くならない。
- [ ] 10分程度の目視運用でQGISが落ちない。
- [ ] NAS/SMB/NFS/VPN上のMP4とローカルSSD上のMP4で体感差を確認し、運用メモへ残す。公開READMEではローカル実行を推奨する。

## 14. 終了時成果物

- [ ] `終了` により生成レイヤが `tmp.gpkg` へ保存される。
- [ ] GPKGから読み込んだ候補/クラスタレイヤを編集せずに `終了` した場合、重い再保存が発生せず終了できる。
- [ ] QGISテーブル上で候補/クラスタfeatureを削除して `終了` した場合、同じ `poi_candidates...` / `poi_clusters...` レイヤ名へ変更が書き戻る。
- [ ] 候補/クラスタレイヤの属性変更やジオメトリ変更後に `終了` した場合、変更済みレイヤだけが保存対象になる。
- [ ] 保存後、生成レイヤがQGISプロジェクトから削除される。
- [ ] `tmp.gpkg` 内の撮影点レイヤ名が `video_gpx_points`、Markingレイヤ名が `geo360_markings` になっている。
- [ ] `tmp.gpkg` を再読込し、`frame` など主要属性が保持されている。
- [ ] `viewer_cache/` は一時キャッシュ、`images/` は成果品予定パスとして混同しない。
- [ ] 表示異常時に、`images/` への抽出、`viewer_cache/` 生成、WEBビューア表示のどこで止まっているかを切り分けられる。
