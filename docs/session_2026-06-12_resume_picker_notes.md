# 2026-06-12 作業記録: 360 Viewer Resume / Picker PoC

この文書は、2026-06-12に実装・整理した 360 Viewer 周辺の仕様、判断理由、現時点の到達点を残すものです。

詳細な計算式やフィールド仕様は `docs/rader_spec.md` に寄せ、この文書では「なぜその仕様にしたか」「現時点で何ができるか」「何をまだ決めていないか」を記録します。

## 今日の主題

当初の主題は、360ビューアで見ている地点を、地図上の地物候補として落とすことでした。

ただし、途中で重要な整理が入りました。

- このビューアは高精度な画像計測器ではない。
- 主目的は、地物登録のために「この辺にこれがあった」を迷わず残すこと。
- 360空間から地図平面への投影は、スクリーニングと作業メモのための補助である。
- 作業者が中断・再開しても迷子にならないことを、精緻な機能追加より優先する。

このため、今日の実装は「地物登録の前段として、見たもの、置いた点、作業条件を再現できる状態」に寄せた。

## 設計方針

### 目的を絞る

ビューア側へ業務固有の地物種別、属性編集、正式レイヤ登録UIを持ち込まない。

ビューア側の責務:

- 360画像を見る。
- 地物候補をダブルクリックで仮置きする。
- クリック点を360空間上に再表示する。
- クリック点を地図平面へ投影するための補助値を渡す。

QGIS側の責務:

- 撮影点とクリック点を地図上に表示する。
- クリック点を一時メモレイヤとして保存する。
- 後段の正式な地物登録、修正、属性追加を受け止める。

この分担により、ビューアを「何でもできるエディタ」にしない。

### データ品質を主語にする

ユーザが知りたいのは、アプリの機能一覧ではなく、今開いているデータの状態である。

そのため、今後のUI改善では以下を優先する。

- このGPKGはどのMP4/GPX/KP CSVから作られたか。
- 撮影点は何件あるか。
- クリック点は何件あるか。
- クリック点があるフレームは何件あるか。
- 校正値は何か。
- MP4実体は見つかっているか。
- 保存先はどこか。
- 最終保存時刻はいつか。

機能説明を増やすより、データ状態を見せる。

### 自由度より集中

自由度が高いUIは、現場作業中の判断コストを増やす。

GPKG読込後は復元作業モードとして扱い、GPX/MP4/KP/Outputの再選択や全件処理を無効化する。入力を差し替える場合は段取り替えとして、一度セッションを終了する。

この制限は不便に見えるが、作業中に別動画由来のアウトプットやレイヤが混在する事故を避けるための仕様である。

## 実装した主な仕様

### 1. 出力フォルダをMP4名にする

従来の既定出力先 `360ViewerOutput` では、複数動画の成果物が同じフォルダへ混在する恐れがあった。

変更後は、選択したMP4と同じフォルダに、MP4のベース名を持つ出力フォルダを作る。

例:

```text
D:/nexco/VID_20260605_140303_00_001_2.mp4
D:/nexco/VID_20260605_140303_00_001_2/
```

これにより、フォルダ名を見るだけで「この動画から生成されたアウトプット」であることが分かる。

### 2. カメラ高さをジョブ条件として扱う

`CamH` は全体プロファイルではなく、撮影時の三脚、車両、治具、カメラ取り付け位置に依存するジョブ個別条件として扱う。

パネルに `CamH` 入力欄を追加し、`viewer_session.json` とGPKGメタデータへ保存する。

360ビューア上の地面範囲円は、このカメラ高さを使って地面上の距離円を投影する。

### 3. 1m補助グリッド

360ビューア上の距離感を読みやすくするため、主円とは別に1m間隔の補助線を追加した。

仕様:

- `Range=5m` の場合、主円は5m/10m。
- `Range=10m` の場合、主円は10m/20m。
- 補助線は `Range` に関係なく1m間隔。
- QGIS地図側にも同じ1m補助円を表示する。
- WEB側は `HUD` ボタンで主円、補助グリッド、距離HUDをまとめて表示/非表示にする。

重要な前提:

この表示は地表面上の距離目安であり、標識板、人物の胴体、壁面、電線など高さを持つ対象物の距離を測るものではない。人や標識柱を見る場合は、足元や根元など地表面との接点を基準にする。

### 4. 360クリック点の複数保存

360ビューア上でダブルクリックした点を、クリック順の複数点として保存する。

QGIS側では、クリック点を `360 Click Targets` メモリレイヤへ保存する。GPKG保存時は内部レイヤ名 `click_targets_360` として保存する。

主な属性:

- `video`
- `frame`
- `target_id`
- `target_order`
- `latitude`
- `longitude`
- `distance_m`
- `forward_m`
- `bearing_deg`
- `yaw_delta`
- `target_yaw`
- `target_pitch`
- `view_yaw`
- `view_pitch`
- `view_zoom`
- `source_lat`
- `source_lon`
- `projection`
- `created_at`

`video` / `frame` / `target_id` の組み合わせで重複登録を避ける。

### 5. クリック点のビューア復元

保存済みクリック点があるフレームを表示した場合、WEBビューア上にも点を復元表示する。

復元は、保存時の画面座標ではなく、保存した `target_yaw` / `target_pitch` を現在視点へ再投影して行う。

この復元は、厳密な画像計測結果の再現ではなく、「どの画像のどの方向へ点を置いたか」を作業者が確認するための表示である。

### 6. Picked point ナビゲーション

クリック点があるGPKGを読んだ場合、ナビゲーションモードを `Picked point` にする。

`Picked point` は `360 Click Targets` の `frame` だけを前後移動する。作業者は、地物候補を置いたフレームだけをブックマークのように見直せる。

このモードでは、現在ユーザが見ている視点を引き継がず、保存済みの `view_yaw` / `view_pitch` / `view_zoom` を再現する。同一フレームに複数点がある場合は、クリック順で最後の点を代表視点として使う。

### 7. GPKG作業状態読込

`tmp.gpkg` から以下の内部レイヤを読み、標準メモリレイヤへ読み替える。

```text
video_gpx_points -> Video GPX Points
click_targets_360 -> 360 Click Targets
```

読み込んだGPKGレイヤを直接編集せず、作業用メモリレイヤとして扱う。
追加クリック点も同じメモリレイヤへ追記し、終了時に再び `tmp.gpkg` へ保存する。
2026-06-21時点では、GPKG由来レイヤを無条件に再保存せず、
feature追加、削除、属性変更、ジオメトリ変更があったレイヤだけ保存対象にする。
これにより、閲覧だけの終了は軽くしつつ、QGISテーブル上で削除・編集したレビュー結果は書き戻せる。

### 8. ジョブメタデータ保存

GPKG内にプラグイン専用のkey/valueテーブル `gpx_video_processor_job_metadata` を保存する。

保存する主な値:

- 元MP4パス
- 元GPXパス
- KP CSVパス
- 出力先
- `Shift`
- `KP tol`
- `Range`
- `Scale`
- `Offset`
- `CalFOV`
- `CalDist`
- `CamH`
- `Follow`
- ナビゲーションステップ

読込時の扱い:

- MP4はビューア表示に実体が必要なため、ファイルが存在する場合だけ動画パスとして復元する。
- GPXとKP CSVは、同期済み座標やKP結果がGPKG内にあるため、ファイルが存在しなくても由来の参照情報として復元する。

これにより、GPKGは単なる一時バックアップではなく、作業状態のレジューム単位になる。

### 9. ダイアログ開始位置の記憶

GPX / MP4 / KP CSV / Output / GPKG の各選択ダイアログについて、最後に使ったフォルダを `QSettings` に保存する。

次回の開始位置は以下の優先順で決める。

1. 現在パネルに入っているパス
2. その種類で前回使った場所
3. 全体で最後に使った場所
4. ホームディレクトリ

頻繁な再開・検証作業で、毎回フォルダを掘り直す摩擦を減らす。

### 10. 専用ビューアウィンドウ

Edge/Chromeが見つかる場合、QGISから360ビューアを `--app=<url>` で独立アプリ窓として開く。

目的:

- 通常ブラウザのタブに埋もれない。
- 作業中はビューアを専用アプリのように扱える。
- 作業終了時に閉じる対象が分かりやすい。

`360viewer/viewer_config.json` の設定:

```json
"viewer_browser_app_window": true,
"viewer_browser_path": ""
```

`viewer_browser_path` が空の場合は、一般的なEdge/Chromeのインストール先を自動探索する。見つからない場合は、従来通り既定ブラウザで開く。

トップURL `http://127.0.0.1:8181` の初期画面が余分に開かないよう、フレーム付き `/viewer?...` が作れる場合だけブラウザを開く。

## 現時点の到達点

現時点でできること:

- GPX/MP4から撮影点を生成する。
- 出力フォルダを動画名単位で分ける。
- 360ビューアを専用ウィンドウで開く。
- QGIS地図と360ビューアの両方で距離目安を確認する。
- 1m補助グリッドで地表面上の距離感を読む。
- 360ビューア上で複数の地物候補をダブルクリックで仮置きする。
- クリック点を地図上の緯度経度として `360 Click Targets` に保存する。
- `tmp.gpkg` に撮影点、クリック点、ジョブメタデータを保存する。
- `tmp.gpkg` を読み戻して、作業状態、クリック点、視点、校正値を復元する。
- `Picked point` でクリック点のあるフレームだけを巡回する。

この状態は、正式な地物台帳作成機能ではなく、地物候補を見つけて残すための作業メモ機能である。

## 現時点で決めた割り切り

### 地表面距離だけを見る

360単眼画像から任意対象物の距離を厳密に測ることはしない。

扱うのは、撮影点から地表面上の点までのおおまかな距離である。標識や電柱など高さを持つ対象物については、根元や足元を基準にする。

### 正式地物登録は別責務

クリック点は仮メモであり、正式な地物台帳レイヤではない。

地物種別、属性、後続補正、正式登録はQGIS側または別プラグイン側で扱う。ビューアは「発見」と「メモ」に集中する。

### GPKGは中間DB

`tmp.gpkg` は作業状態の保存・復元には使うが、そのまま納品DBとは見なさない。

将来、納品用DBにする場合は、レイヤ名、メタデータ、検査レポート、成果品チェックを別途設計する。

### 精度追求より誤差の理解

角度、カメラ高さ、FlowState、スティッチ、レンズガード、実写画角などの影響で、見え方と投影位置はずれる。

今後は、ロープや既知距離チャートを使って実測ずれを確認し、「この用途ではこの程度の誤差で使える」という運用上の落としどころを探す。

## 既知の制約

- カメラ高さの誤差は遠方ほど投影位置へ効く。
- 水平より下向きの視点では、地面投影のずれが目立つ場合がある。
- 同じフレーム内に複数点がある場合、`Picked point` の代表視点は最後の点になる。
- クリック点のビューア復元は完全な見た目再現ではなく、保存yaw/pitchからの再投影である。
- MP4実体が見つからないGPKGでは、地図側のレイヤは復元できるがビューア表示はできない。
- GPX/KP CSVは由来参照として復元できるが、GPKG内の同期済み結果を再生成するためには使わない。
- 通常画角カメラ画像は現時点の対象外。360ビューアとは別モードまたは別ビューアとして設計する。

## 次にやる候補

優先度が高い候補:

- GPKG読込時に、データ状態を短く表示する。
- クリック点数、クリック点ありフレーム数、MP4実体検出有無をパネル上に出す。
- メタデータ有無、最終保存時刻、保存元MP4/GPX/KPを確認しやすくする。
- 実測チャートで、カメラ高さ・pitch・距離のずれを記録する。
- 成果品チェック自動化を設計する。

まだ急がない候補:

- 地物種別入力UI。
- 正式地物レイヤへの直接登録。
- 通常画角カメラ対応。
- 高度な補正パラメータプロファイル。

## 今日の判断として残すこと

このプロトタイプの強みは、自由度の高い汎用ビューアではなく、地物を登録したい作業者の流れへ寄り添うことにある。

そのため、今後も以下を守る。

- 迷う選択肢を増やさない。
- 復元できる状態を増やす。
- 作業者が今見ているデータの品質と由来を分かるようにする。
- ビューア側へ業務固有の重いUIを持ち込まない。
- GIS側の自由度は、後段の修正・正式登録に残す。
